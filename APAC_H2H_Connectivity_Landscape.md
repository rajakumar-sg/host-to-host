# APAC Corporate Host-to-Host (H2H) Connectivity: Peer Landscape

**Prepared:** 10 October 2026 · **Method:** public-source research (bank websites, press releases, help centres, published PDFs) · **Scope:** DBS, OCBC, UOB, HSBC, Standard Chartered, Citi, J.P. Morgan, MUFG, Mizuho, ANZ, CBA, plus non-bank reference rows

**Key:** **Ev.** = evidence grade (A = bank-published technical detail, B = bank marketing page, C = third-party or dated source). **★** = published technical specification or architecture-bearing document. `->` = hop. "(inferred)" = not stated by the bank.

## 2. Executive summary

1. **Rails have converged.** Every bank in scope offers some mix of batch file H2H (SFTP/AS2 plus PGP), APIs and SWIFT (FileAct/SCORE). The discussion is about quality, speed of onboarding and breadth, not whether the rails exist.
2. **Differentiation has moved up the stack:**
   - absorbing client file-format variance (SC Universal Adaptor, ANZ Fileactive translation, UOB transformation layer);
   - ERP-native adaptors and templates (Citi, J.P. Morgan, HSBC);
   - network membership (SAP MBC: Standard Chartered, Citi, Mizuho in June 2026);
   - approval hand-off from H2H into online banking (UOB, ANZ, SC);
   - regional "one bank" platforms (MUFG Unity April 2026, UOB RFTS across 7 markets, ANZ Fileactive across 7 APAC markets, HSBC Connect).
3. **Public technical depth varies widely.** UOB and ANZ publish enough for an architecture sketch (★ rows). J.P. Morgan, SC and MUFG publish format and ERP-adapter specifics. OCBC, DBS, Mizuho and CBA publish little. No bank publishes an end-to-end H2H architecture diagram.
4. **Nobody documents a bank-initiated connection into client ERPs through integration-platform connectors.** The pattern is client-initiated (files or API calls to the bank), a bank-supplied template or adaptor running inside the client's ERP, or a network such as SAP MBC in the middle.
5. **Time-sensitive item:** the ISO 20022 CBPR+ structured/hybrid address change (November 2026) affects H2H file and API submissions (OCBC, SC, MUFG and J.P. Morgan all published notices). J.P. Morgan's page also carries an update saying Swift postponed part of the November release (text truncated in my source). Verify the current enforcement scope and date.
6. **Peer benchmark checklist** (what a competitive APAC H2H offer now includes): file H2H with PGP; API with portal and sandbox; SWIFT FileAct/SCORE; bank-side or self-service format translation; ERP-native templates (SAP first); SAP MBC membership; optional approval hand-off; published acknowledgement levels and SLAs; documented onboarding timeline; CBPR+ readiness.

## 5. Cross-bank reference architecture (my synthesis)

```
Client ERP / TMS
 ├─ (1) Batch file: SFTP / AS2 / FTPS + PGP (encrypt + sign)
 │       -> Bank MFT / file gateway (per-client IN/OUT folders, SSH key, IP allow-list)
 ├─ (2) API: HTTPS REST/JSON + OAuth2/JWT or mTLS (+ PGP payload at DBS)
 │       -> Bank API gateway
 ├─ (3) SWIFT FileAct / FIN / SCORE -> SWIFTNet -> Bank
 └─ (4) Network or aggregator: SAP MBC / FinLync / TMS hub -> Bank tenant or API

Bank side (typical, partly inferred)
 File gateway -> client/partner recognition -> format translation + validation
   -> [optional approval hand-off to online banking: UOB, ANZ Hybrid, SC online release]
   -> payment engine / clearing
   -> acknowledgements (L1-L4 at UOB, pain.002, return status files at ANZ) + statements (camt.052/053, MT940)
   -> back to client over the same rail
```

**Patterns and their meaning (my view)**

| Pattern | Who does it | So what |
|---|---|---|
| Three-rail offer (file, API, SWIFT) | All | Table stakes; the debate is quality and onboarding speed |
| Bank-side format translation | SC Universal Adaptor, ANZ Fileactive, UOB DMP | Reduces per-client mapping effort and rejects; strongest lever for onboarding speed |
| ERP-native templates and adaptors | Citi (SAP DMEE), J.P. Morgan (EBS, D365, SAP), HSBC (SAP) | Shifts mapping work into the client's ERP using standard features |
| Approval hand-off | UOB BIBPlus, ANZ Hybrid, SC online release | Needed for payroll and treasury control |
| Explicit acknowledgement model | UOB L1-L4, ANZ return status files | Gives clients SLAs for reconciliation |
| Network membership | SC, Citi, Mizuho on SAP MBC | Distribution channel into SAP clients; standard formats lower switching cost |
| Regional one-bank platforms | MUFG Unity, UOB RFTS, ANZ Fileactive, HSBC Connect | Multi-country corporates want one H2H contract |
| API portals and sandboxes | HSBC, JPM, UOB, ANZ, SC, Citi | Self-service testing is now expected |
| CBPR+ structured-address readiness | OCBC, SC, MUFG, JPM notices | Affects both file and API rails from November 2026 |

## 6. Capability building blocks suggested by peer practice

1. SAP MBC member-bank onboarding: request the onboarding pack (bank tenant, API specification, connection template) and use the SAP Help Portal "Member Banks" page for the authoritative member list.
2. A client-facing technical specification: protocols, formats, acknowledgement model, onboarding timeline (UOB and ANZ model).
3. ERP-native templates: SAP DMEE first (Citi pattern), then Oracle and Dynamics (J.P. Morgan pattern).
4. A format-translation layer, bank-side or client self-service (SC and ANZ pattern).
5. An optional approval hand-off for payroll and treasury files (UOB, ANZ, SC pattern).
6. Defined acknowledgement levels and SLAs (UOB pattern).
7. API portal and sandbox (HSBC, J.P. Morgan, ANZ, UOB pattern).
8. CBPR+ readiness on both file and API rails ahead of November 2026.
9. Closing evidence gaps (DBS, OCBC, MUFG, Mizuho technical details) through relationship managers, peer contacts and Swift MyStandards.
